## Why this file was written from scratch

Outstanding-issue row `#1S81R8` cites `docs/caring-contacts/hazard-log.md` as an existing record of
hazards H-00, H-04 and H-05, and `#TDKW4W` cites hazard H-44. **No such file has ever existed in
this repository.** `git log --all --name-only` across the full fetched history returns no path
matching `hazard-log`, and the recovery command in
[`phase-1-handoff.md`](phase-1-handoff.md) named a commit that is not a valid object. The
2026-09-02 repository audit records this as finding M6
([`docs/audit/full-repository-audit-2026-09-02.md`](../audit/full-repository-audit-2026-09-02.md),
§M6) and independently confirmed it.

So this is a **reconstruction, not a recovery**. Two consequences the reader must hold onto:

1. **The original wording of H-00, H-04, H-05 and H-44 is lost.** What appears below for those four
   rows is drawn from the ledger rows' own detail cells, which are quoted rather than paraphrased
   wherever the ledger is specific. If the original log said more, this document does not know it.
2. **The original numbering is unrecoverable.** H-01 to H-03, H-06 to H-43 and anything above H-44
   are not in this repository in any form. Those identifiers are therefore **retired and never
   reused here**: hazards newly recorded from the code carry an `H-C##` ("control-derived")
   identifier so that no future reader can mistake a 2026-09-04 reconstruction for a row from the
   lost 2026-08-19 log.

## How to read the columns

- **Existing control** cites the exact `file:line` of the code that enforces the row, and names the
  offline test that proves it runs. Every line number in this document was read at commit time; if
  a citation has drifted, the citation is wrong, not the control.
- **Residual risk** is what the cited control does _not_ cover. It is drafted, not agreed.
- **Status** is one of `UNMITIGATED` (no control exists), `Controlled — unreviewed` (a control
  exists in code and is tested offline, but no clinician has confirmed the control is the right
  one), or `Partial` (a control exists and a known gap is recorded beside it).
- A `Controlled — unreviewed` status is a statement about **code**, not about clinical adequacy.
  Static proof that a rule executes says nothing about whether the rule is correct for a
  suicide-aftercare service. Only the owner can say that, and he has not.

## What this document does not do

- **It does not assess risk.** There is no likelihood, no severity, no risk matrix and no acceptance
  decision anywhere in it, because nobody qualified has made one.
- **It does not certify any control.** "Controlled — unreviewed" means a test passes offline.
- **It does not cover the referral feed, the telephony provider, hosting, authentication at scale,
  or anything the prototype does not contain.** Those are outside what the repository can evidence.
- **It is not a substitute for H-00.** A hazard log with no named clinical safety officer is a
  document with no owner.
